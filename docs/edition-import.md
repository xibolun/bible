# 本地译本导入

在「设置 → 译本管理 → 导入译本文件」选择本地文件，也可从主译本下拉菜单进入管理。识别后先检查来源、版权、覆盖范围和实际经文预览，再确认安装。名称、简称和语言可修改；导入不会自动切换阅读或改变当前投影。点击「开始阅读」才切换到新译本。

文件只在本机处理，不上传、不修改源文件。安装后不再依赖源文件；离线重启后仍可阅读、搜索、高亮、复制、制作卡片及投影。请使用获准在本应用使用的文件。导入能力不授予正文的复制、投影或再分发许可，也不改变应用内置译本的授权范围。

## CrossWire 下载源

「译本管理」内直接切换「已安装／下载译本」，共用搜索、语言筛选、刷新和文件导入入口，无需另开下载列表窗口。下载视图按需读取 CrossWire 官方列表，筛选中文／英文并搜索名称或简称，切换视图保留各自筛选条件。版权与兼容详情在行内展开；不兼容的模块显示原因，不能在应用中下载。选择后显示实际下载进度，可取消；完成后预览实际经文，点击「确认导入」才安装。网络失败可刷新重试，已经安装的译本仍可离线管理和阅读。

已安装列表包含内置 CUV 与用户译本。用户译本可在行内阅读、启停、替换、删除，展开详情可查看报告、版权及恢复旧版；内置译本只提供阅读和版权信息。官方目录中已安装的模块依据保留的来源标识关联，同样提供管理操作；重命名不会丢失关联。

应用使用 [CrossWire 官方模块源](https://www.crosswire.org/sword/modules/ModDisp.jsp?modType=Bibles)的 HTTPS 模块索引及 ZIP，不在启动时自动联网，不提供自定义 URL 或应用内镜像。下载文件仍经过本地格式校验；来源版次／标识发生变化时要求刷新后重试。下载模块原有许可仍适用，正文不会进入应用内置数据或公共安装包。

仅内置中文和合本简体字 CUV；旧 WEBP 阅读与历史引用会回退到可用译本，用户已经导入的译本不删除。只有一个兼容译本时对照开关禁用，安装额外兼容译本后可使用。

## 首期格式

扩展名只是提示，实际按签名、表结构或 XML 根元素识别。以下是已实现并用自编合成样本验证的具体子集，不代表兼容各平台的全部模块。

MySword 官方下载的 `asv.bbl.mybible.gz` 可以直接选择：若浏览器已经解压但保留 `.gz` 文件名，按 SQLite 内容识别；若仍为 GZIP，则在本机自动解压后识别。无需改名。该下载样本的 ASV 2.3.7 已验证，其他模块仍按各自格式检查。

| 格式 | 文件 | 支持配置与边界 |
| --- | --- | --- |
| MyBible | `.SQLite3` | `info(name,value)`、`books(book_number)` 或 `books_all(book_number,is_present)`、`verses(book_number,chapter,verse,text)`；使用 MyBible 固定书卷号映射，不能用 1–66 代替。仅正文模块。 |
| MySword | `.bbl.mybible` | `Details` 单行元数据及 `Bible(Book,Chapter,Verse,Scripture)`，书卷号 1–66。支持明确识别的 GBF／正文样式，以及 ASV 2.3.7 的 font/HEB 包装规则；保留希伯来文正文，不执行来源正则。未知正文替换规则仍拒绝。不包含词典、注释模块。 |
| theWord | `.ont`、`.ot`、`.nt` | 官方 0.10 规格的 UTF-8 未加密文本子集，分别为 31,102／23,145／7,957 个 KJV 引用位置，空行仍占一个位置；正文后读取模块元数据。自定义 `verse.rule`、`tag.rule`、`notags` 渲染规则和加密的 `ontx/otx/ntx` 暂不支持。 |
| OSIS | `.xml`、`.osis` | OSIS 2.1.1 命名空间中的正文子集，支持 `verse` 容器和配对 `sID/eID` 里程碑、书卷代码、诗行及常见行内标记。不能直接读取 SWORD 二进制模块。 |
| Zefania XML | `.xml` | 无命名空间的 `XMLBIBLE/INFORMATION/BIBLEBOOK/CHAPTER/VERS`，按 zef2005 2.0.1 正文子集读取，支持 `STYLE/GRAM/SUP/BR`。识别明确的合并节 `e` 扩展。 |
| SWORD | `.zip` | 一个 `mods.d/*.conf` 与其 `modules/texts/ztext/...` 文件集合。支持未加密 `zText`、ZIP（zlib）压缩、BOOK/CHAPTER/VERSE 块、UTF-8、OSIS 正文和 KJV／NRSV 编号。已验证 Darby 2.0（1889 英文版）：66 卷／1189 章／31,099 条正文；可直接选原 ZIP，无需转换。其他 driver、压缩、编码或编号体系暂不支持。 |
| ZIP 容器 | `.zip` | 其中恰好一个受支持资源或一组 SWORD 模块文件。多个候选时请解压并单独选择；不支持嵌套 ZIP、加密条目、路径穿越或符号链接。 |
| GZIP 容器 | `.gz` | 一个受支持资源，按实际压缩签名识别，校验 CRC 与完整性；拒绝多成员、尾随数据和嵌套压缩，不按头部文件名创建文件路径。 |

SQLite 使用已有驱动以只读方式查询固定表，不执行模块提供的 SQL 或程序；视图、触发器、虚拟表和生成列会被拒绝。XML 不解析 DTD 或外部实体。UTF-8／UTF-16 XML 可读取，历史 GBK／Big5 编码需先可靠转换。未知正文标记、未知书卷或无法解释的引用会阻止导入，避免悄悄丢字。

已识别的脚注、标题、交叉引用、Strong 编号等不导入正文，报告会说明。真实正文的标点、补词括号、组合字符、诗行和换行保留；不翻译、不自动简繁转换、不做 Unicode 归一化。原文注解仍使用既有 KJV Strong’s 来源，不代表导入译本具有逐词关联。

## 部分译本与经节编号

支持 66 卷范围内的完整、旧约、新约或单卷译本，目录只列实际有正文的章。缺节保留缺口，绝不从内置译本补齐或按列表位置重新编号。源标签 `3`、`3a`、`3b`、`3-4` 保留；合并节只显示、搜索一次，复制或投影相交范围时保留完整原记录及实际出处。跨章节或非连续合并引用暂不支持。

经过验证的 theWord KJV 固定行号和 SWORD KJV 索引配置参与自动逐节对照。索引使用独立节号表，不需要内置 KJV 正文。其他导入配置的编号体系暂标为未验证，允许单独阅读、搜索及投影，对照开关会说明限制。修改显示名不能解除此限制。

NRSV 源索引保留约翰三书 1:15 与启示录 12:18 的额外位置，不按 KJV 索引错位读取；目前只支持单独阅读和投影，不启用自动 KJV 对照。

SWORD 模块、两约、卷首和章首的介绍槽位不会错当经节。同一索引指向的连续同章经节合并为一条实际范围；跨章或非连续共享索引会被拒绝。校验索引边界、解压长度及 zlib 校验和，兼容 Darby 中固定的 1024 个零字节填充，不执行模块过滤器。单个解压块最多 32 MiB，累计最多 200 MiB。来源模块文件及正文均不会加入应用安装包。

## 重复、替换与删除

- 相同正文及编号配置再次导入为幂等操作，不重复安装，也不会自动启用已停用的译本；可以明确选择「启用并阅读」。不同正文即使同名也默认另存。
- 「替换」需明确指定用户译本。旧版正文仍保留，可在详情中恢复；高亮按译本 ID 与正文版次隔离，恢复原版时原高亮可再次显示。
- 停用或删除后，阅读和搜索选择回到可用译本；已投影的画面保持快照，再次投放会验证可用性。
- 删除会移除该译本的各版正文，默认保留个人高亮及恢复标识；重新导入相同正文可以恢复关联。勾选「同时删除此译本的所有高亮」会一并清除标记。跨数据库删除中断时，下次启动继续完成，待删除译本不会重新出现在阅读目录。

内置译本不能通过此入口删除。源文件中的来源、版权、版次和元数据可在详情查看；未提供版权信息时明确标注缺失，不推定为公版。

## 存储与限制

用户译本保存在应用配置目录中的 `Bible/editions.sqlite`，与既有 `user.db` 分开。数据库使用独立 schema 1；安装事务完成前不会暴露半成品。未知未来版本或损坏的译本库不会覆盖用户数据，内置阅读仍可使用。临时快照、解析状态和预览 token 属当前会话；预览 30 分钟后失效，未提交的中断任务需重新选择文件。导入正文按章读取，不整库传入前端。

单文件／ZIP 内资源上限 200 MiB，ZIP 最多 128 项、总声明解压大小 512 MiB；最多 100,000 条原始经文，每条正文 64 KiB、合计正文 128 MiB。后台解析限 120 秒，可取消。超限、加密、未知格式和引用错误均显示原因，不安装占位译本。

GZIP 压缩文件及实际解压后资源也各限 200 MiB，在解压过程中检查，不依赖头部声明的大小。

实际经文预览样本只保留在当前会话，不写入持久任务历史，避免删除译本后仍残留样本文字。

浏览器 Mock 仅演示小型 Zefania 测试 XML 和自编中／英文下载示例的界面流程，存储在浏览器本地；完整解析和原生文件选择以桌面实现为准。Linux 原生对话框、安装、删源文件后重启和移除已在本机隔离环境中验证；macOS／Windows 原生对话框仍需对应系统验收。

## 格式依据与后续

实现参考 [MyBible 官方模块格式](https://docs.google.com/document/d/12rf4Pqy13qhnAW31uKkaWNTBDTtRbNW0s7cM0vcimlA/edit)、[MySword 模块说明](https://www.mysword.info/modules-format)、[theWord 官方 0.10 规格](https://www.theword.net/docs/tw3-bible-module-spec.doc)、[CrossWire OSIS 文档](https://wiki.crosswire.org/OSIS_Bibles) 及 [zef2005 XSD](https://svn.code.sf.net/p/bibleworkplace/elberfelder1871/trunk/zef2005.xsd)。这些规范是兼容依据，测试文件的正文均为自编 CC0 合成文本，未随功能增加任何外部译本全文。

SWORD 结构依据为 [CrossWire 配置规范](https://wiki.crosswire.org/DevTools:conf_Files)与[压缩经文索引说明](https://www.crosswire.org/jsword/javadoc/org/crosswire/jsword/book/sword/ZVerseBackend.html)。

后续可发布明确 schema 的 SQLite、JSON、YAML 交换格式并新增独立适配器；当前内部 SQLite 存储不等于支持任意 SQLite 文件。USFM／USX、e-Sword、其他 SWORD 配置、云平台缓存及无结构 PDF／TXT／图片尚不支持。
