# Desktop product decisions

- Go + Wails v3.1.0, with Go 1.26.10. React + strict TypeScript + Vite + Ant Design is the embedded frontend. The desktop uses native local services; no HTTP application server, cloud account, go-zero, MySQL, Redis, or container deployment is introduced.
- The requested book/chapter/verse reading layout takes precedence over the general administration-dashboard layout. Common Ant Design controls, restrained tokens, feedback and keyboard conventions are retained.
- The application bundles simplified Chinese CUV (CrossWire ChiUns 3.1), English WEBP (eBible snapshot 2026-11-13) and KJV (CrossWire/SWORD 3.1), using the 66-book canon. Existing CUV/WEBP text and versions are preserved; KJV has an independent normalized-text fingerprint. Texts align by source verse label, never list position. Two distinct translations can be selected for reading, copying and cards, including English-to-English comparison. NIV is explicitly deferred pending authorized data in Issue #6.
- `VITE_DATA_MODE=mock` selects the visible browser prototype. Native mode uses generated Go bindings and never silently falls back to browser data or storage. Mock and native data are derived from the same pinned conversion.
- Desktop targets are macOS 12+, Windows 11 and Linux on amd64 and arm64. The user's Linux build request supersedes the initial macOS/Windows-only scope. Linux uses GTK4/WebKitGTK 6.0 with Ubuntu 24.04 native CI as the baseline; local package manifests record their own host/libc/library versions. Linux builds require a matching native architecture; no implicit CGO cross-toolchain is assumed. Cross-compiling a Windows binary remains useful verification and does not replace native runtime testing.
- The user explicitly requested public repository visibility. Original application code has no selected open-source license; public visibility alone does not grant one.
- Main is protected. The README-only baseline was committed on a separate bootstrap branch, then used to create main. Implementation belongs to its issue branch and a PR; Linux support continues on issue/3. Nothing in this workflow authorizes a merge or release publication.
- Packaging uses stable Taskfile tasks wrapped by Makefile. Mac packages are ad-hoc signed and not notarized; Windows packages are unsigned internal test artifacts. Developer ID/Windows signing credentials are not bundled or assumed.
- Linux packages are unsigned tar.gz/deb artifacts with owned desktop identity/icons and all legal notices. They use system shared libraries; Debian dependencies are computed from the actual ELF. No install/uninstall maintainer scripts delete user settings or annotations. Runtime file dialogs rely on the desktop portal/backend. AppImage/RPM and universal Linux compatibility are deferred.
- Ubuntu's user-namespace restriction is handled with the vendor-recommended AppArmor profile mode attached only to the Bible executable, allowing `userns` so WebKit can create its sandbox. Debian maintainer scripts load/unload this profile when supported; they do not modify global sysctls or user data. CI relocates the same profile to its exact binary path and keeps WebKit sandboxing enabled.
- Owned icons and plain DMG layout replace template branding. Dependency names and copyright notices remain in third-party license files.
- Native smoke mode is opt-in (`--smoke-test` plus `BIBLE_SMOKE_DIR`), uses isolated test data, exercises the real WebView/Go bridge, clipboard and PNG writing twice, and does not automate native save-dialog interaction or claim manual installation/fullscreen acceptance.
