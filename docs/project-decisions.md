# Desktop product decisions

- User editions use six separate, bounded import adapters (MyBible, MySword, theWord UTF-8, OSIS 2.1.1 Zefania zef2005 and SWORD zText/ZIP/OSIS/UTF-8) and a private `editions.sqlite` schema independent of existing `user.db` schema 1. Partial coverage and original split/joined labels are preserved. The verified theWord KJV line and SWORD KJV index profiles permits automatic comparison; unknown numbering remains usable individually. Immutable versions isolate highlights, explicit replacement retains old versions, and durable removal intent resumes optional annotation purges across restarts. The shared provider supplies reading, LIKE search, clipboard/cards and projection snapshots. This is local personal import, not authorization to redistribute additional scripture. Generic SQLite/JSON/YAML interchange and other platform adapters are deferred; exact profiles are documented in `edition-import.md`.

- Chinese chapter numerals join the original verse label directly in citations (for example, 约三16); Arabic chapter numerals retain the colon (约3:16). The setting controls this rule independently of interface language across native copy/cards and frontend previews/projection. Inline/per-verse reference-to-body punctuation remains separate.

- Original-language study bundles the independent FHL CBOL Chinese dictionary under GNU FDL 1.1-or-later, with unchanged transparent source dumps, publisher notice, license and normalization history in the distribution. Chinese wording remains Traditional Chinese. Separately attributed OSHB (CC BY 4.0) and CrossWire Strong’s Greek (Public Domain) supply original script, transliteration, pronunciation and expandable English definitions. Verse word groups come from the already pinned KJV 3.1 OSIS Strong’s annotations; the UI identifies that source and does not imply word alignment for CUV/WEBP. Scripture text and data versions remain unchanged.
- Four persisted reading palettes (Light, Warm paper, Soft sage and Quiet night) use shared Ant Design tokens and CSS variables across reading, navigation and floating controls. Additive readingTheme preferences preserve schema 1, legacy defaults, reading position and highlights. Scripture and secondary text contrast are checked; highlighted text retains a dark foreground at night. The owned open-book/cross SVG is the single source for platform icons and NSIS artwork; installed-app DisplayIcon points to the branded executable.

- Go + Wails v3.1.0, with Go 1.26.10. React + strict TypeScript + Vite + Ant Design is the embedded frontend. The desktop uses native local services; no HTTP application server, cloud account, go-zero, MySQL, Redis, or container deployment is introduced.
- The requested book/chapter/verse reading layout takes precedence over the general administration-dashboard layout. Common Ant Design controls, restrained tokens, feedback and keyboard conventions are retained.
- The application bundles only simplified Chinese CUV (CrossWire ChiUns 3.1) and English WEBP (eBible snapshot 2026-11-13), using the 66-book canon. Their existing text, data versions and highlights are preserved. KJV/DBY scripture and catalogue entries are removed; stale preferences fall back to available editions. The independent KJV Strong’s study data and attribution remain. TheWord and SWORD use a separate scripture-free KJV chapter/verse count table. Other editions, including Darby, are installed through local import. Texts align by source labels; imported linked verses retain their range exactly once. NIV remains deferred in Issue #6 and Lu Zhenzhong in Issue #24; private import does not authorize bundled redistribution.
- Chapter navigation wraps below the toolbar rather than scrolling horizontally. Reading uses compact 1.55 line height and source verse numbers as whole-passage/Shift-range targets without repeated edition badges. Edge arrows and focus mode are removed; chapter buttons and context-aware Left/Right Arrow shortcuts navigate continuously across books, stopping only at Genesis 1 and Revelation 22. Mixed-translation selections remain rejected; actions anchor near the selection endpoint.
- Offline search uses a selected translation and implicit contains matching with LIKE-style percent/underscore wildcards and backslash escapes. ASCII letters compare case-insensitively; other Unicode characters compare exactly, and underscore consumes one code point. A bounded glob matcher avoids executing SQL or constructing an unsafe backtracking regex. Native and Mock search share golden cases, canonical result ordering and pagination; choosing a hit switches to its translation and verse. Chinese dictionary senses appear before source metadata, with the complete unchanged entry available separately.
- Copying and scripture cards share seven tested reference presets, exact source labels and optional edition text. Block references respect before/after preferences; inline/per-verse styles remain prefixes. Native and Mock adapters use explicit style/language options and user-example golden fixtures. Cards retain line breaks and never silently crop text.
- Verse-row clicks select a complete verse in that translation, with same-translation Shift ranges; partial drag and double-click word selections retain their original offsets. Copy/card references add independent chapter numerals (Arabic/Chinese through 150) and reference-only brackets (none, 【】, 「」, []). Defaults preserve every existing format. Global font size (11–20, default 13) scales both UI and scripture from the existing reading-size baseline; exported card dimensions and fonts remain independent. Additive preferences retain schema 1 and legacy defaults.
- Ctrl/Cmd+, opens Settings, including from editable controls, and repeated invocation preserves the active tab. Ctrl/Cmd+F opens/refocuses scripture search, scripture copy follows reference preferences while editable controls keep native copy/paste, and Ctrl/Cmd+Q saves the current preferences before native quit. macOS supplies a standard editing menu and Settings item, and routes its quit item through the same persistence path. Browser preview reports that its tab must be closed directly; it does not simulate a successful desktop quit.
- Settings provide font size, Chinese/English interface language, copy-reference style/position, a GitHub source link and About. Additive JSON preference fields retain database schema 1 and initialize missing fields from defaults, preserving existing reading position, window state and annotations; interface language does not select scripture editions.
- `VITE_DATA_MODE=mock` selects the visible browser prototype. Native mode uses generated Go bindings and never silently falls back to browser data or storage. Mock and native data are derived from the same pinned conversion.
- Desktop targets are macOS 12+, Windows 11 and Linux on amd64 and arm64. The user's Linux build request supersedes the initial macOS/Windows-only scope. Linux uses GTK4/WebKitGTK 6.0 with Ubuntu 24.04 native CI as the baseline; local package manifests record their own host/libc/library versions. Linux builds require a matching native architecture; no implicit CGO cross-toolchain is assumed. Cross-compiling a Windows binary remains useful verification and does not replace native runtime testing.
- The user explicitly requested public repository visibility. Original application code has no selected open-source license; public visibility alone does not grant one.
- Main is protected. The README-only baseline was committed on a separate bootstrap branch, then used to create main. Implementation belongs to its issue branch and a PR; changes are not automatically merged. The user separately authorized the tag-triggered release policy described below.
- The user explicitly excludes packaging tests from PR/merge checks. PRs run fast code/build/browser validation once; six-platform packaging, native runtime smoke and artifact aggregation are reserved for version releases and manual package requests. Package collection ignores PR-only runs and matches the requested version. Existing main protection and complete-release validation remain in force.
- Packaging uses stable Taskfile tasks wrapped by Makefile. Mac packages are ad-hoc signed and not notarized; Windows packages are unsigned internal test artifacts. Developer ID/Windows signing credentials are not bundled or assumed.
- Linux packages are unsigned tar.gz/deb artifacts with owned desktop identity/icons and all legal notices. They use system shared libraries; Debian dependencies are computed from the actual ELF. No install/uninstall maintainer scripts delete user settings or annotations. Runtime file dialogs rely on the desktop portal/backend. AppImage/RPM and universal Linux compatibility are deferred.
- Ubuntu's user-namespace restriction is handled with the vendor-recommended AppArmor profile mode attached only to the Bible executable, allowing `userns` so WebKit can create its sandbox. Debian maintainer scripts load/unload this profile when supported; they do not modify global sysctls or user data. CI relocates the same profile to its exact binary path and keeps WebKit sandboxing enabled.
- Owned icons and plain DMG layout replace template branding. Dependency names and copyright notices remain in third-party license files.
- Linux icons install in standard hicolor sizes (16–512) and scalable/apps, matching the desktop entry and application ID. A standalone 1024x1024 directory is not registered in common system hicolor themes and therefore does not supply a discoverable icon. Linux CI extracts the actual deb and resolves its icon through GTK4 at menu/Dock sizes; checking only that a PNG exists is insufficient.
- Tagged vX.Y.Z releases reuse the six-target checked native matrix from commits merged into main. All 26 internal bundle files remain validated and retained in Actions. The user's 2026-11-23 decision limits public attachments to Windows amd64 EXE, macOS arm64/amd64 DMG and Linux amd64 DEB; their checksums appear in release notes. Portable archives, JSON reports and other architectures stay in Actions. Publication retries verify compact or legacy layouts and never overwrite public installers. Explicitly requested existing-release cleanup requires a verified backup and preserves retained asset IDs/digests, tag and source. The user explicitly permits github-actions[bot] only for automated releases with temporary GITHUB_TOKEN; manual Git/GitHub writes and commits remain xibolun. Package and interface versions are injected together and checked in native smoke.
- Native smoke mode is opt-in (`--smoke-test` plus `BIBLE_SMOKE_DIR`), uses isolated test data, exercises the real WebView/Go bridge, clipboard and PNG writing twice, and does not automate native save-dialog interaction or claim manual installation/fullscreen acceptance.
